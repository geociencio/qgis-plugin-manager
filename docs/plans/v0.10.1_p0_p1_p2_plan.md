# Remediation Plan P0/P1/P2 — qgis-manage 0.10.1 → 0.12.0

**Date**: 2026-10-25
**Source**: [`qgis_manage_0.10.0_analysis.md`](../research/qgis_manage_0.10.0_analysis.md)
**Baseline**: qgis-manage **0.10.0** (released), 269 tests, 91.03 % combined
coverage, branch gate 90 %, C901 = 0.
**Constraint**: 0.10.0 is already published. Fixes ship as new releases; never
rewrite the tag or PyPI artifacts.
**Status**: P0 implemented in `f4e09ff`, `3909c71`, `b3d2d9d`, `f7d2dea`, `f6396ec`;
P1 implemented in `fe7b8dd`, `5628c26`, `b421542`; 0.11.0 prepared. P2 pending.

## 1. Release train

## 2. P0 — 0.10.1

### P0-1 `fix(deploy): make backup names collision-safe`

**Problem**: `deploy_plugin` uses `datetime.now().strftime("%Y%m%d%H%M%S")` and
`shutil.copytree` without `dirs_exist_ok`. Two deploys in the same second raise
`File exists` after a successful install, exiting 1.

**Change**:
- Use microsecond precision (`%Y%m%d%H%M%S%f`) in the backup name.
- Keep lexicographic sorting in `rotate_backups` working (fixed-width timestamp).
- Add a defensive suffix (`-1`, `-2`, …) if the path still exists, without
  overwriting an existing backup.
- Update the backup test to run two deploys immediately and assert both succeed.

**Files**: `core/deploy.py`, `tests/test_core_deploy.py` / deploy command tests.

**Acceptance**: two consecutive deploys in the same second return 0; two backups
exist (or rotation obeys `max_backups`); names sort chronologically.

### P0-2 `fix(compile): make --type repeatable`

**Problem**: `--type` is a single `argparse` value; `--type resources --type
translations` keeps only translations. Silent stale resources are a release risk.

**Change**:
- Make `--type` `action="append"`, `choices=[...]`, default `None`.
- Normalize in the command:
  - no `--type` → `("all",)`;
  - one or more values → ordered unique list;
  - `all` anywhere → all families.
- Keep `compile_qt_resources(..., res_type)` backward-compatible: accept `str`
  and `Sequence[str]`; normalize internally.
- `count_compile_steps` must count the union, not duplicate counts.
- Keep separate invocations working; document that both forms are supported.

**Tests**: repeated `resources + translations` generates both outputs; duplicate
types counted once; `--type all` unchanged; no type defaults to all.

**Files**: `cli/commands/compile.py`, `core/compile.py`, compile tests, help.

**Acceptance**: both resource and translation outputs are produced in one
invocation; existing single-type behavior and exit codes unchanged.

### P0-3 `fix(package): reject inconsistent --release-version`

**Problem**: `--release-version 9.9.9` changes the ZIP name, but without
`--stamp`/`--sync-version` the packaged `metadata.txt` keeps the project version.
The QGIS portal validates the metadata, not the filename.

**Change**:
- Before building, compare `--release-version` with the effective metadata
  version.
- If they differ and neither `--stamp` nor a successful `--sync-version` makes
  them agree, fail with an actionable error:
  `--release-version 9.9.9 does not match metadata.txt (3.11.0); use --stamp or --sync-version`.
- If `--stamp` is used, the ZIP name and stamped metadata version must both use
  `--release-version`.
- If `--sync-version` is used, sync to `pyproject.toml`; then require
  `--release-version` to equal that value (or omit it).
- Do not silently mutate the source `metadata.txt` just to satisfy the flag.

**Tests**: mismatch without flags exits non-zero; mismatch with `--stamp` succeeds
and ZIP metadata matches; matching version succeeds; unsafe version still rejected.

**Files**: `cli/commands/package.py`, `core/package.py`, package/E2E tests, help.

**Acceptance**: no ZIP can be produced whose filename version differs from its
packaged metadata version when release tooling is used.

### P0-4 `fix(deploy): add --yes for non-interactive purge`

**Problem**: `--purge-backups` asks two `click.confirm` prompts and has no
`--yes`; CI with closed stdin returns 1. `dclean` already supports `--yes`.

**Change**:
- Add `--yes` to `deploy`, meaning “assume yes for confirmations”.
- Apply it to purge, target-directory creation and deploy confirmation; keep
  `--interactive` as the explicit opt-in to prompts.
- `--interactive` + `--yes` is contradictory: error clearly.
- Without `--yes`, behavior is unchanged and prompts remain.

**Tests**: `--purge-backups --yes` removes backups and deploys with no prompt;
without `--yes` prompts; conflicting flags error.

**Files**: `cli/commands/deploy.py`, deploy tests, help.

**Acceptance**: CI can purge+deploy non-interactively; no prompt hangs.

### P0-5 `fix(clean): add --dry-run and protect generated sources`

**Problem**: `clean` deletes every `.py` sibling of `.ui`/`.qrc`, including
versioned generated files required by CI. There is no preview.

**Change**:
- `clean_artifacts(project_root, dry_run=False, keep_generated=False)`.
- CLI flags:
  - `--dry-run`: report exactly what would be removed, delete nothing;
  - `--keep-generated`: skip `.py` files generated from `.ui`/`.qrc`.
- Default behavior remains compatible, but print a warning when a generated
  `.py` appears version-tracked. Detect tracked files with `git ls-files
  --error-unmatch <path>` only when Git is available; never fail clean if Git is
  absent.
- `--dry-run` exits 0 and lists actions in deterministic order.

**Tests**: dry-run deletes nothing; keep-generated preserves `resources.py`;
tracked-file warning appears; normal clean still removes caches/docs/compiled
outputs; no Git repository does not crash.

**Files**: `core/cleanup.py`, `cli/commands/clean.py`, clean tests, help.

**Acceptance**: users can preview and preserve generated sources; CI no longer
loses `resources.py` accidentally.

## 3. P1 — 0.11.0

### P1-1 `perf(repository): prune ignored directories before scanning binaries`

**Problem**: `_find_prohibited_binaries` calls `rglob` once per extension and
runs `IgnoreMatcher` only after traversing `.venv`/`docs` (analysis: 21,541
files, 5.5× package time).

**Change**:
- Replace the three `rglob` calls with one `os.walk(topdown=True)`.
- Prune `dirnames` in place using the matcher and fixed dev/cache dirs; skip
  symlinked directories; never follow them.
- Check only the prohibited extension set; preserve deterministic sorted output.
- Keep public validation results/messages unchanged.

**Tests**: ignored directories are not traversed (mock `os.walk`/spy); nested
ignored dirs; symlink dirs skipped; same findings as before.

**Acceptance**: `--repo-check` output identical; traversal excludes `.venv`,
`docs`, caches and `.qgisignore`d dirs; measurable reduction on the fixture tree.

### P1-2 `perf(deploy): add a per-target content manifest`

**Problem**: each deploy re-reads every source/target file to compare content
(~335 ms on 340 files). Size+mtime alone missed same-size rewrites.

**Design**:
- Cache location: project-local `.qgis-manage/deploy-manifest.json` (ignored by
  default and excluded from packages), keyed by target path.
- Entry: `relpath`, `source_size`, `source_mtime_ns`, `source_sha256`,
  `target_size`, `target_sha256`.
- Flow:
  1. Validate target and manifest schema; on corruption/mismatch, full scan.
  2. If target missing → copy.
  3. If source size/mtime and target size/hash match manifest → skip without
     reading.
  4. Otherwise hash as needed; copy only on digest mismatch.
  5. Write manifest atomically after a successful sync only.
- Never trust manifest paths outside the project root; reject symlinks.
- Provide `deploy --no-manifest` as a compatibility/debug escape hatch.

**Tests**: unchanged second deploy avoids content reads; same-size rewrite is
detected; corrupted/missing manifest falls back; failed deploy does not update
manifest; manifest excluded from packages; symlinks rejected.

**Acceptance**: output identical to current deploy; second incremental deploy is
materially faster; no stale files.

### P1-3 `perf(deploy): use reflink backups when available`

**Problem**: backups copy every byte (11 MB ≈ 30 ms in analysis); on btrfs/xfs
reflinks are near-free.

**Change**:
- On Linux, attempt `cp -a --reflink=auto <src> <dst>`; fall back to
  `shutil.copytree(..., symlinks=True)` on unsupported filesystems or platforms.
- Do not use hardlinks by default (mutating a backup must not mutate the live
  plugin).
- Keep collision-safe naming from P0-1; never overwrite an existing backup.

**Tests**: mocked reflink success; fallback on OSError/non-zero; content equality;
symlink preservation; two-deploy collision regression.

**Acceptance**: same backup content; fallback always safe; no hardlink mutation
risk.

### P1-4 `fix(compile): avoid rewriting identical outputs and skip fresh .qm`

**Problem**: `.qrc`/`.ts` compilation can rewrite identical files every run,
dirtying the working tree; fresh `.qm` files may be rebuilt unnecessarily.

**Change**:
- For QRC/TS, compile to a temporary output, compare bytes with the existing
  output, and replace only when different (atomic replace).
- Skip TS compilation when `.qm` exists and is newer than `.ts`, consistent with
  UI/QRC staleness.
- Preserve failure semantics: failed tool runs do not replace previous outputs.
- Ensure callbacks still emit START/DONE exactly once per file.

**Tests**: identical output preserves mtime/inode; changed output replaces;
fresh `.qm` skipped; stale `.qm` rebuilt; failure preserves old output; callback
counts unchanged.

**Acceptance**: no unnecessary writes; `.qm` freshness honored; no behavioral
regression in compile success/failure.

## 4. P2 — 0.12.0

### P2-1 `feat(cli): add --json to validate, analyze and package`

- Add `--json` to the three commands.
- Emit a single JSON object on stdout:
  ```json
  {"command":"validate","success":true,"errors":[],"warnings":[],"data":{}}
  ```
- Logs/progress go to stderr; stdout stays machine-readable.
- Exit codes remain unchanged (0 success, 1 validation/analysis failure).
- Schema version field (`"schema": 1`) for forward compatibility.
- Tests parse JSON and assert no human text on stdout.

### P2-2 `feat(ignore): add check/explain`

- `qgis-manage ignore check <path>`: exit 0 if excluded, 1 if included.
- `--explain`: print the winning rule, source file/base dir, negation status and
  final decision.
- Reuse the nested-rule model from P3; no duplicate matching logic.
- Tests: root/nested/negation/explain; path outside project errors.

### P2-3 `feat(analyze): pass through --max-cc`

- Add `--max-cc N` and pass it to `qgis-analyzer analyze`.
- Preserve existing command behavior when omitted.
- Tests assert argv shape and exit-code propagation.

### P2-4 `feat(deploy): add --dry-run`

- Compute the sync/backup/purge plan without mutating the target.
- Print deterministic summary: files to copy/delete, backups to create/purge,
  hooks that would run.
- Exit 0; no manifest writes; no hooks executed.
- Tests with a fixture target.

### P2-5 `feat(profiles): add profiles list`

- Detect QGIS profile directories for the selected version and print:
  profile name, path, plugin count, current marker.
- Read-only; no directory creation.
- Handle missing profiles directory with an empty result and exit 0.
- Tests for Linux/macOS/Windows path functions.

### P2-6 `feat(package): add --require-docs`

- Fail before building if `help/html/index.html` is missing.
- Keep default behavior unchanged.
- Tests: missing docs fails; present docs passes; `--require-docs` + `--dev`
  still checks docs.

### P2-7 `feat(hooks)!: make shell=False the default`

- Change `HookPolicy.shell` default to `False`.
- Legacy shell hooks require explicit `shell = true` in project config or an
  explicit policy; print a one-time migration warning when a string command
  cannot be parsed as argv.
- Keep timeout/environment allowlist; update docs with migration.
- This is the intentional breaking change that justifies **0.12.0**.
- Tests: argv command works by default; shell command fails with actionable
  warning; opt-in shell works; Python hooks unchanged.

## 7. Acceptance criteria

### 0.10.1
- Two consecutive deploys succeed.
- `--type resources --type translations` compiles both.
- `package --release-version` cannot produce version-mismatched metadata.
- `deploy --purge-backups --yes` runs non-interactively.
- `clean --dry-run` deletes nothing; `--keep-generated` preserves generated `.py`.
- All 269 existing tests plus new regressions pass.

### 0.11.0
- `--repo-check` traverses no ignored directories and returns identical findings.
- Second deploy uses the manifest and produces identical output.
- Reflink backups fall back safely and preserve content.
- Identical compiled outputs are not rewritten; fresh `.qm` skipped.
- No regression in deploy/compile failure semantics.

### 0.12.0
- JSON output is valid and separated from logs.
- `ignore check/explain` matches nested/negation semantics.
- `analyze --max-cc` reaches the analyzer.
- `deploy --dry-run` mutates nothing.
- `profiles list` is read-only.
- `--require-docs` blocks incomplete packages.
- `HookPolicy(shell=False)` is documented and tested; migration warning present.

## 8. Risks and mitigations

| Risk | Mitigation |
| :--- | :--- |
| `--type` list changes `args.res_type` type | Keep core accepting `str | Sequence[str]`; normalize in one place |
| Release-version validation breaks workflows relying on filename-only override | Clear error with `--stamp`/`--sync-version` guidance; changelog |
| `clean --keep-generated` leaves stale outputs | Document; `--dry-run` shows what is preserved |
| Manifest can hide changes if stale/corrupt | Hash fallback, schema/target validation, `--no-manifest` |
| Reflink unsupported / command injection | Fixed argv, no shell, fallback copytree |
| JSON breaks human scripts | Opt-in flag; exit codes unchanged |
| Shell=False breaks existing hooks | 0.12.0 breaking release, migration warning, config opt-in |
| Performance measurements are machine-specific | Informational benchmarks, no CI time gates |

## 9. Out of scope

- Full Git ignore semantics (`.git/info/exclude`, global excludes).
- Remote plugin marketplace or profile management beyond listing.
- Container sandboxing of hooks/dependencies.
- Parallel deploy; only compile already supports jobs.
- Rewriting or retagging 0.10.0.
