# Plan de refactor y correctitud — 0.16.2 → 0.17.0

**Fecha**: 2026-11-18
**Fuente**: [CODE_SMELLS_v0.16.1.md](../reports/CODE_SMELLS_v0.16.1.md)
**Baseline**: qgis-manage 0.16.1, 426 tests, 96.11 % statements / 90.33 %
branches (94.70 % combinado), C901 = 0, cero dependencias runtime.
**Objetivo**: cerrar primero los riesgos de seguridad/correctitud, después
unificar las políticas de recorrido y los workflows, y finalmente optimizar
rendimiento sin mezclar cambios de comportamiento.
**Estado**: B1–B7 implementados 2026-11-18; B8 release pendiente.
**Per-commit plans**: `docs/plans/commits/README.md`.

## 1. Principios

- No mezclar el patch de seguridad/correctitud con el refactor estructural.
- Cada commit debe quedar verde (tests, ruff, mypy, coverage 95/90, C901 = 0).
- Mantener CLI, mensajes y exit codes salvo que el plan diga lo contrario.
- Mantener `project.dependencies = []` y la política AST de imports.
- Los tests de regresión se añaden en el mismo commit que el fix.
- No introducir nuevas dependencias runtime.

## 3. Fase A — 0.16.2 seguridad y correctitud

### Commit A1 — `fix(hooks): inspect plugin hooks without executing`

- Añadir `discover_hooks(path, execute=False)` en `hooks.py`.
- `hooks list` usa modo inspección AST:
  - `FunctionDef`/`AsyncFunctionDef` con nombres de hooks estándar;
  - no importa ni ejecuta `plugin_hooks.py`.
- `hooks test` y `deploy --trust` conservan la ejecución actual.
- Errores de sintaxis: listar vacío + warning, sin abortar.
- Test: hook que escribe `executed.marker`; `hooks list` no lo crea.

**Acceptance**: listar un repo no confiable no ejecuta código.

### Commit A2 — `fix(deploy): skip nested target in dry-run`

- Reutilizar `_is_same_or_nested` en `plan_deploy`.
- Excluir el target del walk y del conteo, igual que `sync_directory`.
- Test: proyecto con target dentro; dry-run no cuenta archivos del target y no
  desciende en copias anidadas.

**Acceptance**: dry-run y deploy real cuentan el mismo conjunto.

### Commit A3 — `fix(compile): swap docs atomically`

- Compilar en staging fuera de `help/html`.
- Si existe `help/html`, renombrarlo a backup temporal.
- Mover staging a `help/html`; en fallo, restaurar backup.
- Limpiar backup solo tras éxito.
- Test: monkeypatch de `shutil.move` para fallar; `help/html/index.html` previo
  sigue existiendo.

**Acceptance**: un fallo de compilación nunca destruye docs previos.

### Commit A4 — `fix(dclean): resolve absolute profiles`

- Extraer `resolve_profile_dir(profile, qgis_version)` en `core/platform.py` o
  `core/deploy.py`.
- Usarlo en `deploy`, `dclean` y `profiles`.
- Validar que un perfil absoluto sea un directorio de plugins, no cualquier
  directorio; rechazar symlinks peligrosos.
- Test: `dclean --profile <tmp>/plugins` elimina el plugin en esa ruta.

**Acceptance**: `deploy` y `dclean` interpretan igual `--profile`.

### Commit A5 — `fix(compile): serialize progress callbacks`

- Mantener el paralelismo de compilación, pero emitir eventos desde un solo
  hilo consumidor (queue) o proteger el callback con lock.
- Garantizar orden `START`/`DONE` por archivo.
- Test con `jobs=2` y callback que registra `threading.get_ident()`: un único
  hilo emisor y eventos completos.

**Acceptance**: `--jobs > 1` no corrompe el progress bar ni intercala eventos.

### Commit A6 — `fix(package): deterministic ZIP order`

- Ordenar `_collect_zip_items` por `arcname` (o `get_source_files` ordenado).
- Mantener timestamps deterministas y `SOURCE_DATE_EPOCH`.
- Test: crear el mismo proyecto con orden de archivos distinto; los SHA256 de
  los ZIP deben coincidir.

**Acceptance**: build reproducible byte a byte.

### Commit A7 — `chore(release): prepare v0.16.2`

- Changelog, notas, README/help si aplica, métricas.
- Build + `check_distribution.py` + install `--no-deps`.
- Tag y publicación.

**Release**: 0.16.2.

## 4. Fase B — 0.17.0 refactor estructural

### Commit B1 — `refactor(paths): add PathPolicy and ProjectWalker`

- Nuevo módulo `paths/policy.py` con categorías:
  - VCS (`.git`, `.gitignore` cuando aplique);
  - entornos (`.venv`, `venv`, `env`, `libs`, `node_modules`);
  - builds (`build`, `dist`, caches);
  - dev (`tests`, `docs`, `scripts`, `research`);
  - herramientas (`.agent`, `.ai-context`, `.qgis-manage`).
- `ProjectWalker` con:
  - poda de directorios y symlinks;
  - orden determinista;
  - `include_cache_dirs` explícito para `clean`.
- Migrar `compile`, `package`, `cleanup`, `repository` y `discovery`.
- Tests de política por propósito; eliminar listas duplicadas.

**Acceptance**: una sola fuente de exclusión; ningún walker propio.

### Commit B2 — `refactor(deploy): extract DeployWorkflow`

- `DeployRequest`, `DeployPlan`, `DeployResult` en `core/deploy.py`.
- Mover backup, sync, manifiesto, hooks y compilación fuera del comando.
- `DeployCommand.execute` solo:
  1. parsea/valida flags;
  2. llama `prepare`;
  3. confirma;
  4. llama `execute`;
  5. renderiza.
- Corregir el doble `confirm` de `_purge_backups`.
- Tests de flujo: dry-run, purge, perfil absoluto, hooks trust/no trust.

**Acceptance**: `DeployCommand.execute` < 30 líneas y sin lógica de negocio.

### Commit B3 — `refactor(package): extract PackageWorkflow`

- `PackageRequest`/`PackageResult`.
- Un único `create_plugin_package` con opciones condicionales.
- `--json` siempre emite envelope, también en fallo de compliance.
- Tests de JSON en éxito y fallo.

**Acceptance**: sin llamadas duplicadas ni contratos JSON incompletos.

### Commit B4 — `refactor(cli): rename console alias`

- `from .. import console as click` → `from .. import console`.
- Sustituir `click.echo/style/confirm/prompt/progressbar` por `console.*`.
- Actualizar `patch("...click.confirm")` a `console.confirm`.
- Sin cambio de salida.

**Acceptance**: cero alias `as click`; tests verdes.

### Commit B5 — `refactor(cli): typed error boundary`

- `CliError` para errores esperados (validación, trust, IO).
- `BaseCommand.run` captura `CliError`, y deja propagar bugs inesperados.
- `CLIApp.run` captura y ofrece `--debug`/traceback.
- `logger.exception` en errores inesperados.
- Tests de exit code y de traceback solo con `--debug`.

**Acceptance**: los bugs no se convierten silenciosamente en "Error: ...".

### Commit B6 — `fix(toml): atomic version updates`

- `set_project_version` usa `write_text_atomic`.
- Soportar `'1.2.3'` y `"1.2.3"`.
- Test de fallo de escritura: el archivo original permanece.

### Commit B7 — `fix(security): validate external inputs`

- `install-deps`: validar PEP 508, insertar `--`, rechazar `-` inicial.
- `init --template`: whitelist y comprobación de prefijo resuelto.
- ZIP: límites de `file_size` total/por archivo antes de `zf.read`.
- Analyzer: timeout configurable y cache de disponibilidad.
- Tests negativos para cada caso.

### Commit B8 — `chore(release): prepare v0.17.0`

- Changelog/notas, métricas, build, distribución y publicación.

**Release**: 0.17.0.

## 5. Fase C — 0.17.x rendimiento

Solo después de A y B, y con benchmark reproducible:

1. **Un solo inventario** para compile/package/clean; evitar walks duplicados.
2. **CompilePlan** compartido entre `count_compile_steps` y
   `compile_qt_resources`.

5. **`plan_deploy` con manifiesto** para reutilizar huellas.
6. **Benchmark** con 1.000 archivos y 3 escenarios: deploy dry-run, package y
   clean; documentar antes/después.

- Tests actuales + regresiones pasan.

## 8. Riesgos

| Riesgo | Mitigación |
| :--- | :--- |
| Refactor cambia comportamiento de deploy | Tests de flujo y comparación dry-run/real |
| Walker único rompe exclusiones específicas | Política por propósito + tests de tabla |
| Error boundary oculta fallos | `--debug` y tests de traceback |
| Serialización de callbacks reduce rendimiento | Medir jobs=1/2/4; lock mínimo |
| ZIP ordenado cambia checksums esperados | Actualizar golden test una vez y documentar |
| Mezclar fases | Tags 0.16.2 y 0.17.0 separados; no features B2 |
